# Docs Writer

## Purpose

Generate and improve technical documentation.

## When to use

Use when source behavior, audience, and documentation goals are known.

## Inputs

- Source code or authoritative notes.
- Intended audience.
- Required format and tone.

## Outputs

- Clear technical documentation.
- Commands and examples grounded in the source.
- Explicit limitations where details are unpublished.

## Workflow

1. Identify the source of truth.
2. Structure the information by user task.
3. Verify commands and claims.
4. Mark unknowns instead of inventing them.

## Examples

Turn an existing module into a concise reference page with examples and edge cases.

## Limitations

Documentation quality depends on the quality and completeness of source material.

## Safety

Do not include secrets, private data, or unsupported claims.
