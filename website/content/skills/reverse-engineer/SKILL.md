# Reverse Engineer

## Purpose

Assist with legitimate binary and software analysis.

## When to use

Use for software you are authorized to inspect, debug, audit, or understand.

## Inputs

- Binary or source material.
- Analysis objective.
- Known platform and constraints.

## Outputs

- Observations about program structure and behavior.
- Hypotheses tied to evidence.
- Validation suggestions.

## Workflow

1. Establish provenance and scope.
2. Map observable structure and behavior.
3. Separate facts from hypotheses.
4. Validate important conclusions against additional evidence.

## Examples

Build a static analysis plan for an owned binary and document evidence supporting each conclusion.

## Limitations

Experimental specification; conclusions may require manual validation.

## Safety

Use only on software you are authorized to analyze. Do not use the workflow to obtain unauthorized access or bypass controls.
